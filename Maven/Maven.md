=================
DEPENDENCIES
=================

Dependency is an artifact that could be a jar or a pom

Transitive Dependency 		-  		your project depends on an artifact which in turn has a dependency on another artifact

Dependency Mediation 		- 		maven determines what version to use when multiple versions of the same dependency are encountered


Dependency Scope
Compile					-		default scope. available on all classpaths of a project. propogated to downstream projects
Provided					-		like compile, but expected to be provided by JDK or container at runtime.
Runtime					-		the dependency is not required for compiling but needed for runtime
Test						-		the dependency is only available on test classpath
System					-		like Provided, but JAR is added to system explicitly (via file path)
Import					-		imports dependency of POM, allows for inheritance

================
PHASES
================

A phase is a sequence of goals (each goal comes from a plugin). When the phase is run all of it’s goals are executed

all the ‘default’ Build lifecycle phases in order:
  validate					-	check if all information necessary for the build is available
  initialize 
    generate-sources
    process-sources
    generate-resources
    process-resources
  compile					-	compile the source code
    process-classes
    generate-test-sources
    process-test-sources
    generate-test-resources
    process-test-resources
    test-compile				-	compile the test source code
    process-test-classes
  test						-	test the compiled source code using a suitable unit testing framework. These tests should not require the code be packaged or deployed
    prepare-package
  package					-	package the compiled code into a distributable format, e.g. JAR
    pre-integration-test
    integration-test			-	process and deploy the package if needed to run integration tests
    post-integration-test
  verify					-	run any checks on results of integration tests to ensure quality criteria are met
  install					-	install the package to a local repository, for use as a dependency in other projects locally
  deploy					-	copy the package to the remote repository


NOTE: 
 - depending upon the packaging type chosen a combination of default lifecycle phases are executed (but always following the order above) 
 - the configuration comes from default-bindings.xml
 - phases named with hyphenated words (e.g. integration-test) are not usually called from the command line. This is because these phases produce intermediate results that are not useful outside the build.



	‘default’ Build lifecycle phases for ejb/ejb3/jar/par/rar/war packaging
	  process-resources			-->		resources:resources
	  compile					-->		compiler:compile	uses the ‘javax.tools.JavaCompiler’ by default, can be configured to use ‘javac’
  	  process-test-resources		-->		resources:testResources
  	  test-compile				-->		compiler:testCompile
 	  test						-->		surefire:test		for unit testing, supports JUnit 3, JUnit 4, JUnit 5 and TestNG
  	  package					-->		jar:jar
 	  install					-->		install:install
 	  deploy					-->		deploy:deploy		deploy project artifacts to remote Maven repositories


	Note: 
 	- in POM under <build><plugins><plugin> we can bind a phase that is not in the default lifecycle phase list for jar packaging (e.g. initialize) to a plugin goal (e.g. clean:clean) and then that phase will run as well


	‘default’ Build lifecycle phases for ear packaging

HOW TO ASSIGN TASKS TO BUILD PHASES (i.e. phases of one of the Build lifecycles) FOR YOUR PROJECT
======================================================================================

1. Set the packaging type via POM element <packaging>
Each packaging contains a list of goals to bind to a particular phase
Look at the jar packaging and the goals and phases for ‘default’ Build lifecycle


2. Via Plugins
Add the plugin to your POM as well as the phase and goal of the plugin in its execution element

	1	 <plugin>
	2	   <groupId>com.mycompany.example</groupId>
	3	   <artifactId>display-maven-plugin</artifactId>
	4	   <version>1.0</version>
	5	   <executions>
	6	     <execution>
	7	       <id>dmp-time</id>
	8	       <phase>process-test-resources</phase>
	9	       <goals>
	10	         <goal>time</goal>
	11	       </goals>
	12	     </execution>
	13	   </executions>
	14	 </plugin>

In the above case the ‘time’ goal of the display-maven-plugin has been bound to the ‘process-test-resources’ phase of the ‘default’ build lifecycle with an id of ‘dmp-time’
The id is just a label to help identify the plugin:goal in the output


If the phase is not specified then the plugin should know which goal gets bound to which phase

================================
COMMON COMMANDS AND OPTIONS
================================

RUN A PHASE OF A BUILD LIFECYCLE

mvn <phase>
e.g: mvn compile					This is running the all phases up to the compile phase of the ‘default’ build lifecycle



RUN A GOAL OF A PLUGIN

Note: 
 - the below format is <plugin-prefix>:<goal> OR <plugin-group-id>:<plugin-artifact-id>[:<plugin-version>]:<goal>
 - a plugin can be specified by coordinates: ‘org.apache.maven.plugins:mvn-compiler-plugin:3.17’ OR just by its name ‘compiler’
 
Get the OS environment variables and Java System properties
mvn help:system

List all goals bound to a specific phase and their plugins (call describe goal of help plugin with arguments)
mvn help:describe -Dcmd=<phase_name>, e.g. mvn help:describe -Dcmd=compile

Get the effective pom of a project
mvn help:effective-pom

See available plugins for the current project
mvn help:effective-pom | grep -A1 artifactId

Run compile goal of compiler plugin 
mvn compiler:compile

Resolve dependencies for a project (run the resolve goal of the dependency plugin)
mvn dependency:resolve

See dependencies and transitive dependencies 
mvn dependency:tree [-Dscope=runtime]

Clear artifacts from local repository
dependency:purge-local-repository

Get sources for all dependencies
dependency: sources

List all goals in a plugin (run the help goal on that plugin)
mvn <plugin>:help, e.g. mvn compiler:help

Get the classpath after maven has compiled software		(dont forget about packaging here)
mvn -q exec:exec -Dexec.executable=echo -Dexec.args="%classpath" | sed 's|:|\n|g'

Create a maven wrapper for your project
mvn -N io.takari:maven:wrapper -Dmaven=3.6.3		(you can specify any maven version you want)

Generate a project from an archetype 
of ‘maven-archetype-simple’:
mvn archetype:generate -DarchetypeGroupId=org.apache.maven.archetypes -DarchetypeArtifactId=maven-archetype-simple -DarchetypeVersion=1.4

of ‘camel-archetype-spring-boot’:
mvn archetype:generate -DarchetypeGroupId=org.apache.camel.archetypes -DarchetypeArtifactId=camel-archetype-spring-boot -DarchetypeVersion=4.0.0.redhat-00005 -DgroupId=com.redhat -DartifactId=csb-app -Dversion=1.0-SNAPSHOT -DinteractiveMode=false
